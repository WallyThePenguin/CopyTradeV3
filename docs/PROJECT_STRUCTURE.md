# Project Structure & Responsibilities

Use this guide to navigate CopyTradeV2’s codebase and see which folders power the frontend dashboard, middleware/API surface, Discord bot, and ML backend.

## Top-Level Layout
| Path | Responsibility |
| --- | --- |
| `src/` | Node.js runtime: Discord bot, Express/HTTPS gateway, REST routes, WebSockets, services, and React dashboard source. |
| `api/` | Python FastAPI + Mistral LLM service, market-data cron jobs, GPU helpers, and virtual environment. |
| `prisma/` | Prisma schema, migrations, SQLite database (`prisma/data/dev.db`), and seed script. |
| `docs/` | Architecture, roadmap, GGUF maintenance, and this structure guide. |
| `model/` | On-disk GGUF weights loaded by the FastAPI service. |
| `data/` | Logs and trade history snapshots generated by the Node worker. |

## Backend: Discord Bot & Node Services (`src/`)
- `src/index.js` – entry point for the Discord worker, queue management, Mistral calls, callout/trade orchestration, and WebSocket initialization.
- `src/config/channels.js` – declarative channel configuration (short/long-form, confidence, webhooks).
- `src/services/` – core backend services:
  - `tradingService.js`, `robinhood.js`, `robinhoodSimulator.js` – live vs simulated execution, broker API integration.
  - `tradeTracker.js`, `calloutService.js`, `advancedTradeAnalysis.js`, `auditLogger.js` – trade lifecycle, callout persistence, analytics, and audit logs.
  - `mistral.js`/`mistral.refactored.js` – Node-side helpers for the Python LLM service.
- `src/utils/` – logging, error helpers, env validation, data-quality scripts.
- `src/data/` – JSON snapshots or temporary trade files used by services.

## Middleware & API Gateway (`src/web/`)
- `src/web/server.js` – HTTPS Express server, TLS bootstrap, WebSocket initialization, and middleware wiring.
- `src/web/middleware/` – `security.js` (helmet/CORS/rate limiting), `auth.js` (API/admin key validation), `logging.js`, `index.js` aggregator.
- `src/web/routes/` – REST API definitions:
  - `api.js` (composite router) and `routes/v1/*.js` (channels, trades, charts, market, stats endpoints).
- `src/web/broadcast.js` & `src/web/websocket.js` – WebSocket server setup plus helper broadcasts (`trade_opened`, `metrics_update`, etc.).
- `src/web/cron.js` – background jobs (data quality, performance, cleanup) triggered from the server startup.
- `src/web/utils/` – shared helpers for the dashboard and API layer.

## Frontend Dashboard (React/Vite)
- `src/web/App.tsx` plus `Dashboard.tsx`, `ChannelsPage.tsx`, `UsersPage.tsx`, `CalloutsPanel.tsx`, `TradeLog.tsx`, `PerformanceMetrics.tsx`, `TraderProfile.tsx`, `TradersTable.tsx` – SPA pages and components fed by REST + WebSocket data.
- `src/web/main.tsx`, `src/web/index.html`, `vite.config.js` – Vite bootstrap and build configuration.
- `dist/` – production build output served by Express.

## Python / LLM Service (`api/`)
- `mistral_server.py` – FastAPI application, llama.cpp integration, trade context, channel analysis scheduler, webhook hooks.
- `analysis/channel_analyzer.py` – analytics jobs that sync with Prisma data.
- `market_calendar.py`, `market_news.py` – scheduled market data updaters.
- `utils/gpu.py`, `utils/logger.py` – GPU tuning and logging utilities.
- `requirements.txt`, `venv/` – Python dependencies and virtual environment.

## Data, Models, and Credentials
- `model/mistral-7b-instruct-v0.2.Q4_K_M.gguf` – active GGUF weight file (see `docs/LLM_MODEL_MAINTENANCE.md`).
- `data/logs/`, `api/data/logs/` – runtime log output from Node and Python services.
- `.env`, `.env.example` – environment variable configuration for both runtimes.
- `server.cert`, `server.key`, `start-secure-server.js` – local TLS assets and launch script.

## Supporting Files
- `package.json`, `package-lock.json` – Node dependencies and scripts.
- `requirements.txt` / `api/requirements.txt` – Python dependency lists.
- `scripts/` – operational helpers (e.g., Robinhood login/account scripts).
- `.vscode/`, `.cursor/` – editor configuration (optional).

Use this map alongside `docs/SYSTEM_OVERVIEW.md` to understand how new features should be wired end-to-end.
